# 录音功能技术方案文档

> 本文档详细描述了 React Native 项目中端到端加密录音功能的完整实现方案，供在其他 RN 项目中复制参考。
>
> **本仓库落点（utter-office）**：原生以 `apps/mobile/modules/encrypted-recording` Expo Module 注册（不是 RN `RecordingPackage`）；文件 API 为 `expo-file-system`；会话指针走 `expo-secure-store`；回放只用 `expo-audio`（`enableBackgroundRecording` 必须关闭，避免与 `RecordingService` 抢前台服务）。采集参数、分段加密、manifest 对账、10 个事件与下文一致。传输层（HTTP / ASR WS）本期走 Stub。

## 四、加密分段存储结构



### 4.1 目录结构

```
DocumentDirectoryPath/
  rec/
    {sessionId}/                    # 随机 16 字节 hex 目录名
      .manifest                     # 加密的 JSON manifest
      {random_hex_32chars}          # 加密段文件 1
      {random_hex_32chars}          # 加密段文件 2
      {random_hex_32chars}          # 加密段文件 3
      ...
      export.m4a                    # 导出合并文件（解密后转封装）
```



### 4.2 段文件格式

每个 segment 文件：

```
[16 bytes nonce]              ← 随机 IV
[4 bytes encrypted index]     ← AES-CTR 加密的段序号
[AES-CTR encrypted ADTS frames...]  ← 加密的 AAC 音频数据
```



### 4.3 Manifest 格式

`.manifest` 文件：

```
[16 bytes nonce]
[AES-CTR encrypted JSON]:
{
  sessionId: string,
  createdAt: number,
  format: "aac",
  sampleRate: 22050,
  channels: 1,
  state: "recording" | "interrupted" | "finalized",
  totalDurationMs: number,
  segments: [
    {
      index: number,
      file: string,
      nonce: string,
      sampleCount: number,
      durationMs: number,
      byteLength: number,
      sealed: boolean
    }
  ],
  mergeStatus: "none" | "merging" | "ready" | "failed",
  mergedFile: string | null,
  mergedByteLength: number | null,
  mergeError: string | null
}
```

## 五、录音流程详解



### 5.1 开始录音

```typescript
// JS 层
beginFromConsent() {
  // 1. 检查存储/电量
  await checkStorageBeforeRecord()
  
  // 2. 创建服务端录音
  const { recordingId } = await POST('/app/recordings')
  
  // 3. 获取/创建主密钥
  const masterKey = await nativeGetOrCreateRecordingMasterKey()
  
  // 4. 构建会话目录
  const sessionDir = `${DocumentDirectoryPath}/rec/${sessionId}/`
  await RNFS.mkdir(sessionDir)
  
  // 5. 请求麦克风权限
  await ensureMicrophonePermission()
  
  // 6. 启动原生加密录音
  await nativeStartEncryptedRecording(
    sessionDir,
    masterKey,  // Base64 编码
    0,          // 起始段索引
    0           // 基础时长
  )
}
```

**Android 原生流程：**

```kotlin
RecordingModule.startEncryptedRecording()
```

## 六、密钥管理



### 6.1 Android

```kotlin
RecordingMasterKey {
  // 1. AndroidKeyStore 创建 AES-256 GCM 密钥（标记完整性）
  // 2. 实际会话密钥存储在 SharedPreferences("meeting_recording_crypto_v1")
  // 3. 首次调用生成 32 字节随机数 → Base64 存储
  // 4. 后续直接读取返回
  
  fun getOrCreate(): String {
    val keyStore = KeyStore.getInstance("AndroidKeyStore")
    keyStore.load(null)
    
    if (!keyStore.containsAlias("meeting_recording_integrity")) {
      // 创建完整性密钥
      val keyGenerator = KeyGenerator.getInstance(
        KeyProperties.KEY_ALGORITHM_AES, "AndroidKeyStore"
      )
      keyGenerator.init(
        KeyGenParameterSpec.Builder(
          "meeting_recording_integrity",
          KeyProperties.PURPOSE_ENCRYPT or KeyProperties.PURPOSE_DECRYPT
        )
        .setBlockModes(KeyProperties.BLOCK_MODE_GCM)
        .setEncryptionPaddings(KeyProperties.ENCRYPTION_PADDING_NONE)
        .setKeySize(256)
        .build()
      )
      keyGenerator.generateKey()
    }
    
    // 读取或生成会话密钥
    val prefs = context.getSharedPreferences("meeting_recording_crypto_v1", Context.MODE_PRIVATE)
    return prefs.getString("master_key", null) ?: run {
      val key = ByteArray(32).also { SecureRandom().nextBytes(it) }
      val encoded = Base64.encodeToString(key, Base64.NO_WRAP)
      prefs.edit().putString("master_key", encoded).apply()
      encoded
    }
  }
}
```



### 6.2 iOS

```swift
RecordingMasterKey {
  // 1. Keychain 存储 (kSecClassGenericPassword)
  // 2. account: "meeting_recording_master_key_v1"
  // 3. accessible: kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly
  // 4. 首次生成 32 字节随机数
  
  static func getOrCreate() throws -> String {
    let query: [String: Any] = [
      kSecClass as String: kSecClassGenericPassword,
      kSecAttrAccount as String: "meeting_recording_master_key_v1",
      kSecAttrAccessible as String: kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly,
      kSecReturnData as String: true
    ]
    
    var result: AnyObject?
    let status = SecItemCopyMatching(query as CFDictionary, &result)
    
    if status == errSecSuccess, let data = result as? Data {
      return data.base64EncodedString()
    }
    
    // 生成新密钥
    let key = Data(count: 32).map { _ in UInt8.random(in: 0...255) }
    let addQuery: [String: Any] = [
      kSecClass as String: kSecClassGenericPassword,
      kSecAttrAccount as String: "meeting_recording_master_key_v1",
      kSecAttrAccessible as String: kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly,
      kSecValueData as String: key
    ]
    
    SecItemAdd(addQuery as CFDictionary, nil)
    return key.base64EncodedString()
  }
}
```

## 七、原生事件系统

从原生到 JS 的事件通过 `NativeEventEmitter` 传递：


| 事件名                               | 触发时机     | Payload                                              |
| --------------------------------- | -------- | ---------------------------------------------------- |
| `onRecordingTick`                 | ~1Hz 计时  | `{elapsedSeconds}`                                   |
| `onRecordingStopped`              | 停止完成     | `{status, path, fileSize, errorCode}`                |
| `onRecordingError`                | 错误       | `{code, message}`                                    |
| `onRealtimePcmFrame`              | PCM 数据帧  | `{base64, bytes}`                                    |
| `onAppResumedWhileRecording`      | App 回到前台 | `{}`                                                 |
| `onRecordingSystemInterrupted`    | 来电等中断    | `{reason, elapsedSeconds, segmentCount, autoPaused}` |
| `onRecordingSystemInterruptEnded` | 中断结束     | `{canResume}`                                        |
| `onRecordingMergeSkipped`         | 合并跳过     | `{reason, pendingCount}`                             |
| `onRecordingMemoryPressure`       | 内存压力     | `{level}`                                            |
| `onRecordingForceStop`            | 强制停止     | `{reason, path, segmentPaths}`                       |

## 十、中断处理（来电等）



### 10.1 Android

```kotlin
// EncryptedSessionHost.kt
private fun registerCallListener() {
  val telephonyManager = context.getSystemService(Context.TELEPHONY_SERVICE) as TelephonyManager
  
  telephonyManager.listen(object : PhoneStateListener() {
    override fun onCallStateChanged(state: Int, phoneNumber: String?) {
      when (state) {
        TelephonyManager.CALL_STATE_RINGING,
        TelephonyManager.CALL_STATE_OFFHOOK -> {
          // 来电或通话中 → 暂停
          pause(interruption = true)
          emitSystemInterrupted("phone_call")
        }
        TelephonyManager.CALL_STATE_IDLE -> {
          // 通话结束 → 恢复（仅当被中断暂停时）
          if (pausedByInterruption) {
            resume()
            emitSystemInterruptEnded(canResume = true)
          }
        }
      }
    }
  }, PhoneStateListener.LISTEN_CALL_STATE)
}
```



### 10.2 iOS

```swift
// RecordingModule.swift
private func setupAudioInterruptionHandler() {
  NotificationCenter.default.addObserver(
    self,
    selector: #selector(handleAudioInterruption(_:)),
    name: AVAudioSession.interruptionNotification,
    object: nil
  )
}

@objc private func handleAudioInterruption(_ notification: Notification) {
  guard let userInfo = notification.userInfo,
        let typeValue = userInfo[AVAudioSessionInterruptionTypeKey] as? UInt,
        let type = AVAudioSession.InterruptionType(rawValue: typeValue) else {
    return
  }
  
  switch type {
  case .began:
    // 中断开始 → 暂停
    encryptedEngine.requestPause()
    emitSystemInterrupted("audio_session")
    
  case .ended:
    // 中断结束 → 恢复
    guard let optionsValue = userInfo[AVAudioSessionInterruptionOptionKey] as? UInt else {
      return
    }
    let options = AVAudioSession.InterruptionOptions(rawValue: optionsValue)
    let shouldResume = options.contains(.shouldResume)
    emitSystemInterruptEnded(canResume: shouldResume)
  }
}
```

## 十一、崩溃恢复机制



### 11.1 Manifest 对账

```kotlin
// EncryptedSessionHost.kt
fun reconcileSession() {
  // 1. 扫描 session 目录
  val files = sessionDir.listFiles() ?: return
  
  // 2. 对每个未 sealed 的段文件
  files.filter { it.name.matches(Regex("^[0-9a-f]{32}$")) }
    .forEach { file ->
      // 3. 解密 → 截断到最后一个完整 ADTS 帧 → 重新加密写回
      SegmentWriter.recoverUnsealedFile(file, masterKey)
      
      // 4. 合并到 manifest
      manifest.addSegment(file)
    }
  
  // 5. 保存 manifest
  manifestStore.save(manifest)
}
```

## 十二、实时 ASR 流程

```typescript
// RealtimeAsrService.ts
class RealtimeAsrService {
  async start(config: AsrConfig) {
    // 1. WebSocket 连接
    this.ws = new WebSocket(config.wsUrl)
    
    // 2. 等待握手
    await this.waitForHandshake()
    
    // 3. 开启 PCM 采集
    await nativeStartRealtimePcm()
    
    // 4. 监听 PCM 帧事件
    this.subscription = NativeEventEmitter.addListener(
      'onRealtimePcmFrame',
      (event) => this.handlePcmFrame(event)
    )
  }
  
  private handlePcmFrame(event: { base64: string, bytes: number }) {
    // 5. 拆分为 3200 bytes 帧（腾讯云 ASR 限制）
    const chunks = this.splitIntoChunks(event.base64, 3200)
    
    // 6. 逐帧发送
    chunks.forEach(chunk => {
      this.ws.send(chunk)
    })
  }
  
  private splitIntoChunks(base64: string, size: number): string[] {
    const bytes = Buffer.from(base64, 'base64')
    const chunks: string[] = []
    
    for (let i = 0; i < bytes.length; i += size) {
      const chunk = bytes.slice(i, i + size)
      chunks.push(chunk.toString('base64'))
    }
    
    return chunks
  }
}
```

```swift
func resampleForAsr(buffer: AVAudioPCMBuffer) -> AVAudioPCMBuffer? {
  let inputFormat = buffer.format
  let outputFormat = AVAudioFormat(
    commonFormat: .pcmFormatInt16,
    sampleRate: 16000,
    channels: 1,
    interleaved: true
  )!

    outStatus.pointee = .haveData
    return buffer
  }
  
  return status == .haveData ? outputBuffer : nil
}
```

## 十三、分片上传流程

```typescript
// ChunkUploader.ts
class ChunkUploader {
  async upload(filePath: string, recordingId: string) {
    const fileSize = await RNFS.stat(filePath).then(s => s.size)
    const totalChunks = Math.ceil(fileSize / CHUNK_SIZE)
    
    // 1. 查询已上传分片（断点续传）
    const { uploadedChunks } = await GET(`/recordings/${recordingId}/upload-status`)
    
    // 2. 并行上传未完成的分片（2 并发）
    const pendingChunks = range(totalChunks).filter(i => !uploadedChunks.includes(i))
    
    await pMap(pendingChunks, async (chunkIndex) => {
      const start = chunkIndex * CHUNK_SIZE
      const end = Math.min(start + CHUNK_SIZE, fileSize)
      
      // 3. 读取 2MB
      const chunk = await this.readChunk(filePath, start, end)
      
      // 4. 计算 SHA256
      const hash = await this.calculateSha256(chunk)
      
      // 5. 上传（最多重试 3 次）
      await this.uploadChunkWithRetry(recordingId, chunkIndex, chunk, hash, 3)
    }, { concurrency: 2 })
    
    // 6. 完成上传
    await POST(`/recordings/${recordingId}/upload-complete`, {
      totalChunks,
      fileSize,
      hash: await this.calculateFinalHash(filePath)
    })
  }
  
  private async uploadChunkWithRetry(
    recordingId: string,
    chunkIndex: number,
    chunk: Buffer,
    hash: string,
    maxRetries: number
  ) {
    for (let attempt = 0; attempt < maxRetries; attempt++) {
      try {
        await POST(`/recordings/${recordingId}/upload`, {
          chunkIndex,
          data: chunk.toString('base64'),
          hash
        })
        return
      } catch (error) {
        if (attempt === maxRetries - 1) throw error
        await sleep(RETRY_BACKOFF[attempt])
      }
    }
  }
}
```

### 15.4 CTR 加密对齐

**坑：** iOS 手动实现 AES-CTR（CommonCrypto 无原生 CTR 模式），必须用 ECB + XOR 模拟

```swift
// iOS 需要手动实现 CTR 模式
func aesCtrEncrypt(data: Data, key: Data, nonce: Data) -> Data {
  var result = Data()
  let blockSize = 16
  var counter = 0
  
  for i in stride(from: 0, to: data.count, by: blockSize) {
    // 1. 构造计数器块：nonce + counter
    var counterBlock = nonce
    counterBlock.append(UInt32(counter).bigEndianBytes)
    
    // 2. ECB 加密计数器
    let encryptedCounter = aesEcbEncrypt(counterBlock, key: key)
    
    // 3. XOR 数据
    let chunk = data[i..<min(i + blockSize, data.count)]
    let encrypted = chunk.enumerated().map { (j, byte) in
      byte ^ encryptedCounter[j]
    }
    
    result.append(contentsOf: encrypted)
    counter += 1
  }
  
  return result
}
```

**注意：** `byteOffset` 参数要对齐 Android 的 `Cipher.update()` 流式行为

### 15.5 ADTS 帧解析

```kotlin
// AdtsUtil.kt
fun findLastCompleteAdtsFrame(data: ByteArray): Int {
  var lastFrameStart = 0
  var offset = 0
  
  while (offset < data.size - 6) {
    // ADTS 同步字：0xFFF
    if (data[offset] == 0xFF.toByte() && (data[offset + 1].toInt() and 0xF0) == 0xF0) {
      // 解析帧长度（6 字节头）
      val frameLength = ((data[offset + 3].toInt() and 0x03) shl 11) or
                       ((data[offset + 4].toInt() and 0xFF) shl 3) or
                       ((data[offset + 5].toInt() and 0xE0) shr 5)
      
      lastFrameStart = offset
      offset += frameLength
    } else {
      offset++
    }
  }
  
  return lastFrameStart
}
```

## 十七、性能优化建议

1. **分段大小：** 30 秒/段是平衡点，太小会增加文件数量，太大会增加内存占用
2. **上传并发：** 2 并发是推荐值，太多会占用带宽
3. **ASR 帧大小：** 3200 bytes 是腾讯云限制，不要超过
4. **前台服务通知：** 同一秒不重复 notify，避免性能问题
5. **Manifest 写入：** 使用原子写入，避免损坏
