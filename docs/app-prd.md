## 1. 产品主张与范围

### 1.1 一句话

> **开口或按一下，上下文进小队；数字员工在 Runtime 上推进；你只拿成果、看进度、做审批。**

### 1.2 五层结构

| 层 | 问题 | Tab |
|----|------|-----|
| 成果层 | 有什么可拿走？什么要我决定？ | 首页 |
| 进度层 | 进行到哪？谁卡了？ | 看板 |
| 入口层 | 如何低摩擦喂 Context / 下达？ | ●录 |
| 编排层 | 派给谁？组什么队？细节与指令？ | 工作台 |
| 资产层 | 员工 / 技能 / 知识 / Runtime / 交接？ | 我的 |

### 1.3 HITL（贯穿，硬性）

> 人在关键环节保留介入：派活可改、过程可见、结果可收可退、异常必须找人。

| 环节 | 用户动作 | 产品表现 |
|------|----------|----------|
| 派活前 | 改指派 / 优先级 / 小队 | 派活 CTA、picker |
| 执行中 | 看 steps、补指令、取消 | 事项详情 + Composer |
| 结果 | 验收 / 回退 | 首页成果卡、详情 CTA |
| 异常 | 处理阻塞 | 需我处理、看板 blocked |

**检查项：** 任何「AI 正在做」的 UI，同屏或一跳内可达「看 / 停 / 改 / 验」。

### 1.4 本期做（文档 + 原型阶段）

1. 冻结 v2 叙事与 IA（本 PRD + 蓝图）。  
2. 原型与讲解壳与本 PRD 一致（另开「改原型」计划；App 不动）。  
3. 登记后端缺口（§12），不实施。  
4. 保留录音加密内核方案作为 Context 采集底座（实装期再接）。

### 1.5 本期不做

| 不做 | 原因 |
|------|------|
| 改 `apps/mobile` | 用户要求先计划改原型 |
| 任何后端改动 | 联调面失控；只登记 |
| BLE / 通知 Context 采集 | 无协议；属 M5 |
| 完整 ASR 生产引擎 | Stub / 分期 |
| StaffDeck 竞标 arena / OKF 深移植 | 领域与成本；见蓝图 |
| 绑死单一消费级 Agent 品牌 | 开放执行原则 |


- 选中态：图标井浅蓝 + brand；badge 用 brand。

### 3.2 必须跑通的主路径

| # | 路径 | 验收点 |
|---|------|--------|
| P1 | 首页成果「验收」→ 工作台事项详情 → 验收/回退 | 非进空会话 |

## 4. 首页 — 拿成果

### 4.1 定位

混合视角：**上半管理者向（小队成果），下半执行者向（待我处理直达）**。  
3 秒内回答：可拿走什么 / 要我处理什么。

### 4.2 布局（上→下）

1. **顶栏**：问候 + 工作区微标；右：待我处理（badge）+ 搜索  
2. **阻断条**（若有）：工位未绑定等，链到档案能力  
3. **小队今日成果**  
   - 摘要：今日交付 / 待验收 / 阻塞（A 类）  
   - 横向成果卡：类型（PR/纪要/方案…）· 归属 · **验收 / 打开 / 转发**  
4. **需我处理**：类型徽标 阻/选/验；深链事项详情  
5. **小队在推进**（次级）：生命周期 chip + 简进度  
6. **主动洞察**：商机/风险/待办落地/对齐；建议动作 + 建议指派；「去处理」

### 4.3 交互规则

- 成果卡主按钮进 **工作台事项详情**，禁止进聊天空会话。  
- 洞察禁止做成资讯排行（无红序号热榜心智）。  
- 空态：无成果时引导「派活」或「录音捕获灵感」。

### 4.4 相对 v1.8

废止：大 Hero 派单墙、Pulse 入口墙、行业简报排行主区块、把「工作成果」完全迁走导致首页只看不拿。

### 4.5 验收

- [ ] 首屏同时出现「可拿走」与「需我处理」信号  
- [ ] 至少一条深链 `?issue=` 可演示  
- [ ] 洞察带建议指派与行动 CTA

## 6. 中央 ●录 — Context 入口

### 6.1 产品语义

> 目标不是「更好的录音工具」，而是 **AI 时代的 Context 入口**：快速产生驱动 Agent 的要素。

| 入口 | 用途 | Agent 关系 |
|------|------|------------|
| 录音 | 会议 / 访谈 / 碎片想法 | M3：转写 → 行动信号 |
| 翻译 | 双语场景 | 独立能力 |
| 发语音 | 即时下达 | 指令入队 |

对用户文案避免单独强调「录音卡」；可用「捕捉上下文 / 下达 / 录音」。

### 6.2 交互（与现网对齐处）

- 短按：Sheet 三入口  
- 长按 ≥ 阈值：Overlay；松手 Toast **不发送**（保持现网，直至产品改决）  
- 录音页：本机加密采集按 [`录音实现方案.md`](./录音实现方案.md)；转写/纪要未接前为 B 类示例  

### 6.3 场景（产品故事，实装分期）

| 场景 | 期望体验 |
|------|----------|
| 灵感捕捉 | 按住说完 → Agent 收到 → 回来拿结果 |
| 会议 | 录音结束 → 事项候选 → 确认派活 |
| AI 访谈 | 长对话 Context → 草案交付物待验收 |

### 6.4 远期（M5，本 PRD 不实施）

通知 Push 采集、BLE 硬件、灯效回传——单开硬件/系统权限 PRD。

### 6.5 验收

- [ ] Sheet 三入口可达  
- [ ] 讲解/设置文案体现 Context，而非纯录音笔  
- [ ] 录音加密路径文档可引用

## 7. 工作台 — 安排活

### 7.1 定位

**编排台**：像派同事一样派数字员工。  
对话 = 下达/补充指令通道，**不是**默认主舞台。

### 7.2 默认态：编排台

1. 顶栏：小队名 + Runtime 微标 + **派活**  
2. 劳动力条：人 + 员工；在岗/忙碌/队列；点成员 = 筛其队列（非开聊）  
3. 「组队执行」入口  
4. 三段板：**待派发 | 进行中 | 待验收**  

### 7.3 事项详情态（同页切换或等价路由）

- 生命周期时间线：enqueue → claim → start → blocked/review → complete/fail  
- 实时执行流（steps / tool calls）  
- 交付物区  
- 验收通过 / 回退修改  
- 底部 Composer：补充指令（标明通道属性）  

### 7.4 深链

`/{slug}/workbench?issue=<KEY>` 打开对应详情；未知 key 时回编排台并 toast。

### 7.5 相对 v1.8

废止默认「StaffRail + 气泡占满屏」。会话能力可保留在详情下达通道或次级入口，不得作为冷启动首页。

### 7.6 验收

- [ ] 冷启动不是聊天  
- [ ] 三段板可切换  
- [ ] 详情含生命周期 + 交付物 + 验收  
- [ ] Composer 文案为下达/补充，非「发消息给好友」

## 10. 设计与文案约定

### 10.1 视觉

- 沿用现有 brand token（`#3B6FFF` 等），不另起紫色/玻璃拟态体系。  
- 进度、生命周期 chip、小队叠头像、成果卡等共用件以原型 `_shared.css` 为准。  

### 10.2 文案

- 用户可见文案中文。  
- 状态枚举：**只改展示值，不改 key / 顺序**（parity）。  
- 避免「秘书陪聊」「员工频道」作为主导语；改用「派活 / 小队 / 验收 / 上下文」。  

### 10.3 中英混用

技术标识（Runtime、PR、Issue key）可保留；句子级说明用中文。

## 11. 数据分级与 Mock

沿用 v1.8 三级（决策不造假）：

| 级 | 含义 | 缺数据时 |
|----|------|----------|
| **A** | 决策数字/状态 | 显示 `——` + 说明，禁止假数 |
| **B** | 内容阅读 | 可 mock +「示例数据」徽标 + 可关 |
| **C** | 结构骨架 | 固定假值可 |

**A 类示例：** 交付数、阻塞数、待验数、在岗、失败率、未读 HITL 数。  
**B 类示例：** 洞察正文、示例成果描述、录音转写示例。  

原型阶段允许全 mock，但讲解壳须标明「原型」。App 实装期严格执行本表。

## 15. 风险与未决

### 15.1 风险

| 风险 | 缓解 |
|------|------|
| App 长期落后于原型 | D1 后尽快 M1；PRD 为真源 |
| Outcome 无后端 | 先客户端聚合 issue+附件；B-OUT 登记 |
| 用户仍找「聊天」 | 工作台提供「下达」入口但不默认会话墙 |
| Context 隐私 | 加密录音；洞察可关；授权最小化 |
| Feature 焦虑 | 锁管道，抵制散点 |

| 后端 | 只登记 |
| App | 待 D1 原型计划后再改 |
